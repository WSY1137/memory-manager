# Memory Manager · 闸门系统配置

> **版本**：v2.0.1
> **说明**：记忆管理器的所有闸门与全局配置。修改本文件可调节记忆管理器的行为。
> **位置**：`~/.trae-cn/memory/memory-config.md`

---

## 配置总览

```
用户请求
   │
① G1 Trigger      触发闸门    ──→ 要不要加载 Skill？
   │
② G2 Intent       意图闸门    ──→ 明确要执行还是随便提？
   │
③ G3 Quality      质量闸门    ──→ 值不值得做？
   │
④ G4 Process      流程闸门    ──→ 按多完整的流程走？
   │
  执行业务逻辑
   │
⑤ G5 Write        写入闸门    ──→ 能不能写入文件？
   │
⑥ G6 Safety       安全闸门    ──→ 破坏性操作保护
   │
  完成
```

## 一、闸门配置（Gate Configuration）

### G1 · 触发闸门（Trigger Gate）

控制是否加载本 Skill。
等级越高，触发条件越严格，越不容易被误触发。

| 配置项 | 当前值 | 可选值 | 说明 |
|---|---|---|---|
| `strictness` | `medium` | `strict` / `medium` / `loose` | 触发严格程度 |
| `auto_trigger` | `true` | `true` / `false` | 是否允许自动触发（false 则仅强触发词生效） |

**各等级行为**：
- `strict` — 仅精确名称 `memory-manager` 或"记忆管家""记忆管理"触发
- `medium` — 精确名称 + 自然语言触发（"查记忆库""查经验库""记忆库有没有"等）
- `loose` — 所有相关表达都触发，弱触发需确认

---

### G2 · 意图闸门（Intent Gate）

触发后，判断用户是否真的要执行该功能，还是只是随口提到。

| 配置项 | 当前值 | 可选值 | 说明 |
|---|---|---|---|
| `strictness` | `medium` | `strict` / `medium` / `loose` | 确认严格程度 |
| `confirm_on_weak` | `true` | `true` / `false` | 弱触发时是否先确认意图 |

**各等级行为**：
- `strict` — 任何情况都先确认"你是要我做 XXX 吗？"
- `medium` — 强触发直接执行，弱触发先确认
- `loose` — 都直接执行，不确认

---

### G3 · 质量闸门（Quality Gate）

执行前检查"值不值得做"，防止生成空洞内容浪费算力。

| 配置项 | 当前值 | 类型 | 说明 |
|---|---|---|---|
| `archive_min_files` | `3` | 整数 | 归档最少改动文件数（低于则提示确认） |
| `archive_min_changes` | `50` | 整数 | 归档最少改动行数（低于则提示确认） |
| `knowledge_dedup_check` | `true` | 布尔 | 加入知识库前是否做重复检查 |
| `pitfall_min_confidence` | `medium` | `high`/`medium`/`low` | 踩坑记录的最低置信度要求 |
| `review_min_material` | `3` | 整数 | 记忆复盘最少素材数（项目/会话数） |
| `tidy_min_entries` | `10` | 整数 | 记忆整理最少条目数（低于则没必要整理） |

**各功能的质量检查项**：

| 功能 | 检查项 | 不通过时 |
|---|---|---|
| 项目归档 | 改动文件数 + 改动行数 | 提示"改动较小，确定要归档吗？" |
| 知识提炼 | 普适性 + 重复度 | 建议只加入项目记忆，不加全局 |
| 偏好复盘 | 素材数量 | 建议"素材不够，再多做几个项目后再复盘" |
| 记忆整理 | 记忆条目数 | 提示"记忆不多，暂时不需要整理" |

---

### G4 · 流程闸门（Process Gate）

决定按多完整的标准流程执行。

| 配置项 | 当前值 | 可选值 | 说明 |
|---|---|---|---|
| `strictness` | `adaptive` | `strict` / `adaptive` / `loose` | 流程严格程度 |
| `skip_after_confirmed` | `true` | 布尔 | 用户确认过的步骤，后续可跳过 |
| `user_familiarity` | `new` | `new` / `learning` / `familiar` | 用户熟悉程度（影响自适应） |

**各等级行为**：
- `strict` — 始终走完整标准流程，每步都说明
- `adaptive` — 自适应调整（推荐）：
  - 新用户 → 完整流程 + 详细说明
  - 熟练用户 → 简化流程，跳过不必要说明
  - 用户说"快点""直接来" → 尽量简化
  - 任务简单 → 简化；任务复杂 → 完整流程
- `loose` — 怎么高效怎么来，尽量省略步骤

---

### G5 · 写入闸门（Write Gate）

控制记忆写入的保守程度。

| 配置项 | 当前值 | 可选值 | 说明 |
|---|---|---|---|
| `strictness` | `medium` | `strict` / `medium` / `loose` | 写入严格程度 |
| `require_source` | `true` | 布尔 | 每条记忆是否必须标注来源 |
| `require_tags` | `false` | 布尔 | 每条记忆是否必须加标签 |
| `confirm_before_write` | `true` | 布尔 | 写入前是否必须展示并确认 |

**各等级行为**：
- `strict` — 所有写入都确认，必须有来源和标签
- `medium` — 新增确认、更新提示、标注来源，标签可选
- `loose` — 小改动不确认，仅重要内容确认，来源和标签可选

---

### G6 · 安全闸门（Safety Gate）

破坏性操作的额外保护。安全闸门没有严格程度等级——安全就是安全。

| 配置项 | 当前值 | 类型 | 说明 |
|---|---|---|---|
| `backup_before_batch` | `true` | 布尔 | 批量修改前是否备份 |
| `delete_confirm_level` | `strict` | `strict` / `medium` | 删除确认严格程度 |
| `batch_threshold` | `5` | 整数 | 批量操作阈值（≥ N 条记忆算批量） |
| `backup_retention` | `5` | 整数 | 备份保留数量（最多保留 N 份） |

**触发安全闸门的操作**：

| 操作 | 安全措施 |
|---|---|
| 删除记忆条目 | 二次确认 + 显示删除内容 |
| 批量修改（≥ batch_threshold 条） | 确认 + 备份 |
| 覆盖式更新（非追加） | 显示 diff + 确认 |
| 记忆整理（自动修改多条） | 展示完整修改计划 + 确认 + 备份 |
| 偏好复盘（批量新增） | 列出所有条目 + 确认 |

**备份规则**：
- 备份目录：同目录 `.backup/`
- 命名格式：`{filename}.backup.{YYYYMMDD-HHmmss}.md`
- 保留数量：`backup_retention` 份，超出自动清理最旧的

## 三、快速预设（Presets）

如果你不想逐个调节，可以直接使用下面的预设。

### 🔒 严格模式（Strict）
适合：对记忆质量要求高、不怕多确认几次
```
G1: strict, G2: strict, G3: 提高阈值, G4: strict, G5: strict
```

### ⚖️ 标准模式（Standard）—— 默认
适合：大多数用户，在质量和效率之间平衡
```
G1: medium, G2: medium, G3: 默认阈值, G4: adaptive, G5: medium
```

### ⚡ 宽松模式（Loose）
适合：已经很熟悉了，想尽量减少交互步骤
```
G1: loose, G2: loose, G3: 降低阈值, G4: loose, G5: loose
```

> **切换方法**：在对话中说"切换到严格模式""用标准模式""调宽松一点"即可。

## 四、配置修改说明

### 手动修改
直接编辑本文件，修改对应配置项的值。下次记忆管理器触发时自动生效。

### 对话中修改
直接对 AI 说：
- "把触发闸门调成严格模式"
- "归档最少文件数改成 5"
- "切换到宽松模式"
- "重置为默认配置"

AI 会展示修改前后的 diff，确认后写入。
