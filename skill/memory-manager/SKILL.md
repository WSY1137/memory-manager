# Memory Manager · 记忆管理器

> **版本**：v1.0.0
> **类型**：全局 Skill
> **适用场景**：AI 记忆的全生命周期管理
> **最后更新**：2026-10-08

---

## 一、概述

记忆管理器是一套面向 AI 记忆全生命周期的管理系统，覆盖**采集 → 提炼 → 存储 → 检索 → 维护 → 归档**完整链路。

核心设计原则：
- **配置驱动**：所有行为通过闸门配置调节，无需修改核心逻辑
- **质量优先**：六级闸门控制系统，确保记忆质量，避免算力浪费
- **灵活可控**：三级灵活度（刚性/推荐/可选），平衡规范性与适应性
- **安全保守**：写入必确认、删除必二次确认、批量必备份
- **人类可读**：全 Markdown 存储，可直接编辑、版本友好

## 四、闸门控制系统

所有操作通过 **六级闸门** 进行质量与成本控制。闸门配置见 `memory-config.md`。

```
用户请求
   │
① 触发闸门 ──→ 是否加载本 Skill？（strict/medium/loose）
   │ 通过
   ▼
② 意图闸门 ──→ 是否明确要执行？（strict/medium/loose）
   │ 通过
   ▼
③ 质量闸门 ──→ 这件事值不值得做？（阈值检查）
   │ 通过
   ▼
④ 流程闸门 ──→ 按多完整的标准流程？（strict/adaptive/loose）
   │
   ▼
  执行业务逻辑
   │
   ▼
⑤ 写入闸门 ──→ 结果能否写入持久化存储？（strict/medium/loose）
   │ 通过
   ▼
⑥ 安全闸门 ──→ （破坏性操作）额外确认与备份
   │
   ▼
  完成
```

### 各闸门说明

#### ① 触发闸门（Trigger Gate）
控制是否加载本 Skill，避免不必要的上下文占用。
- **strict**：仅强触发词生效
- **medium**：强触发 + 功能触发生效
- **loose**：所有相关表达都触发（弱触发需确认）

#### ② 意图闸门（Intent Gate）
触发后，确认用户是否真的要执行该功能，还是只是随口提到。
- **strict**：任何情况先确认
- **medium**：强触发直接执行，弱触发先确认
- **loose**：都直接执行

#### ③ 质量闸门（Quality Gate）
执行前检查是否有足够内容/增量，避免生成空洞内容浪费算力。
- 归档：检查改动规模（文件数/行数），低于阈值提示确认
- 知识提炼：检查普适性与重复度
- 记忆复盘：检查素材量（至少 3 个项目/会话才有意义）
- 记忆整理：检查记忆条目数（太少没必要整理）

#### ④ 流程闸门（Process Gate）
决定执行流程的繁简程度。
- **strict**：始终走完整标准流程
- **adaptive（自适应）**：根据用户熟悉度、任务复杂度动态调整
- **loose**：尽量简化，怎么高效怎么来

#### ⑤ 写入闸门（Write Gate）
控制记忆写入的保守程度。
- **strict**：所有写入都确认，必须有来源和标签
- **medium**：新增确认、更新提示、标注来源
- **loose**：小改动不确认，仅重要内容确认

#### ⑥ 安全闸门（Safety Gate）
破坏性操作的额外保护。安全闸门没有严格程度等级——安全就是安全。
- 删除 → 二次确认
- 批量操作（≥5 条）→ 确认 + 备份
- 覆盖更新 → 显示 diff 再确认
- 备份目录：同目录 `.backup/`，最多保留 5 份

## 五、灵活度原则

本 Skill 的指令分为三级，AI 可根据上下文灵活调整。

| 等级 | 标记 | 可调？ | 说明 |
|---|---|---|---|
| 🔴 刚性规则 | Must | ❌ 绝对不行 | 安全底线，任何情况都不能违反 |
| 🟡 推荐流程 | Should | ⚠️ 合理可调整 | 建议遵循，但有更好的做法时可以偏离 |
| 🟢 可选建议 | May | ✅ 自由发挥 | 仅供参考，AI 可根据场景自由选择 |

**偏离流程的前提**：
1. 不违反刚性规则
2. 结果质量不下降
3. 用户不会感到困惑
4. 偏离后简要说明原因

**优先级**：用户明确指令 > 🔴 刚性规则 > 🟡 推荐流程 > 🟢 可选建议

## 六、刚性规则清单（Must Not Violate）

以下规则绝对不能违反：

1. **写入确认** — 任何写入记忆文件的操作，必须先向用户展示修改内容并获得确认
2. **删除确认** — 删除任何记忆条目，必须二次确认并显示将要删除的内容
3. **批量备份** — 修改 ≥ 5 条记忆的批量操作，必须先备份再执行
4. **配置读取** — 执行任何操作前，先读取 `memory-config.md` 获取当前闸门配置
5. **来源标注** — 所有 AI 提炼的记忆条目，必须标注来源（项目/日期）
6. **保守提取** — 不确定的信息标记为"待确认"，不直接写入
7. **隐私保护** — 不记录密码、密钥、个人隐私等敏感信息

## 七、核心功能

### 7.1 项目归档（Project Archive）

**触发**：`归档` `项目归档` `项目总结` `记录一下这个项目`

**用途**：项目/功能完成后，生成结构化归档文档，提炼项目知识，沉淀可复用经验。

**标准流程**：
1. 读取闸门配置
2. 收集项目信息（目录结构、文件列表、Git 历史、规划文档）
3. 质量闸门检查（改动规模是否足够）
4. 生成归档文档（基于 archive-template.md）
5. 提炼项目知识 → 更新 project_memory.md
6. 识别可复用经验 → 询问是否加入全局知识库
7. 保存归档文档到项目 archive/ 目录
8. 展示归档摘要，等待用户确认写入

**输出结构**：
- 改动概览（新增/修改文件、核心模块）
- 技术选型与关键决策
- 核心实现说明
- 踩坑记录
- 遗留问题与后续优化
- 可复用经验提炼

---

### 7.2 知识库检索（Knowledge Retrieval）

**触发**：`查知识库` `知识检索` `之前有没有遇到过` `类似的经验`

**用途**：从全局知识库和历史归档中检索相关经验，避免重复踩坑。

**标准流程**：
1. 理解用户问题（领域、技术栈、问题类型）
2. 读取知识库全部文件
3. 搜索项目归档（如有相关项目）
4. 多维度匹配（关键词 + 标签 + 语义相关度）
5. 按相关性排序
6. 返回结构化结果列表
7. 询问是否需要展开某条详情

**匹配维度**：
- 关键词匹配（标题 + 正文）
- 标签匹配（技术标签 + 类型标签）
- 分类匹配（问题属于哪个知识库分类）
- 时间衰减（越新的经验权重越高）

---

### 7.3 记忆整理（Memory Tidy）

**触发**：`整理记忆` `记忆整理` `清理记忆` `记忆优化`

**用途**：清理重复、合并矛盾、优化分类、标记过时，保持记忆库健康。

**标准流程**：
1. 读取全部记忆文件
2. 执行五项分析：
   - 重复检测（内容相似或重复的条目）
   - 矛盾检测（互相冲突的记忆）
   - 分类检查（放错位置的条目）
   - 过时标记（> 90 天未更新且可能失效）
   - 格式检查（缺少来源、标签、结构不统一）
3. 生成整理报告，分三类：
   - ✅ 可自动处理（明确重复、格式调整）
   - ⚠️ 需要确认（矛盾判断、过时条目）
   - 💡 优化建议（分类调整、结构优化）
4. 用户确认后，执行修改（先备份）

---

### 7.4 偏好复盘（Preference Review）

**触发**：`记忆复盘` `偏好复盘` `提炼偏好`

**用途**：从近期项目和对话中识别行为模式，提炼稳定偏好，更新全局画像。

**标准流程**：
1. 收集素材（近期归档文档 + 会话摘要 + 当前全局记忆）
2. 多维度模式识别：
   - 技术栈偏好（反复使用的框架/工具）
   - 编码风格（命名习惯、代码组织、注释风格）
   - 沟通偏好（详细/简洁、结论先行/过程先行）
   - 工作流习惯（Plan 模式/直接干、写不写测试）
3. 按置信度分级（高/中/低）
4. 生成复盘报告
5. 高置信度条目经确认后，写入 user_profile.md

**置信度判定参考**：
- **高**：≥ 3 个独立项目/场景中一致出现
- **中**：2 个项目中出现，或多次对话中提到
- **低**：只出现 1 次，或证据不充分

## 八、通用工作流

### 8.1 初始化检查

每次执行记忆操作前，先检查记忆系统是否完整：
1. 检查 memory-config.md 是否存在
2. 检查 knowledge/ 目录及四个文件是否存在
3. 如果有缺失，询问用户是否自动创建

### 8.2 备份策略

执行以下操作前必须备份：
- 批量修改 ≥ 5 条记忆
- 删除操作
- 覆盖式更新（非追加）

备份规则：
- 备份位置：同目录 `.backup/`
- 命名格式：`{filename}.backup.{YYYYMMDD-HHmmss}.md`
- 保留数量：最多 5 份，自动清理最旧的

### 8.3 写入确认规范

所有写入操作必须：
1. 清晰展示将要修改的内容
2. 说明修改的位置（哪个文件、哪个分类）
3. 获得用户明确确认后再执行
4. 执行后反馈结果

### 8.4 错误处理

| 场景 | 处理方式 |
|---|---|
| 记忆文件不存在 | 询问是否创建，不自动创建 |
| 文件格式异常 | 提示用户，不要猜测修改 |
| 权限不足 | 告知用户手动操作 |
| 配置读取失败 | 使用默认配置并提醒用户 |
