## 2026-10-08 · v1.0.0 骨架搭建

### 背景

用户反馈 TRAE 的记忆功能内容很少，只有一两条。讨论后发现：
1. TRAE 原生记忆的自动提取能力有限，只识别非常明确的偏好
2. 没有项目归档机制，做完的项目知识就流失了
3. 没有跨项目的知识复用能力
4. 记忆管理缺乏可视化和系统化的体验

因此决定做一个**记忆管理器 Skill**，弥补 TRAE 原生记忆功能的不足。

### 开发目标

- 项目做完后，说一声就能自动归档沉淀
- 知识库能跨项目复用经验
- 记忆能自动/半自动整理
- 有统一的入口和可视化概览
- 质量可控，不浪费算力

### 架构设计

#### 五级记忆体系

```
L1 会话记忆 (topics.md)
  → L2 项目记忆 (project_memory.md)
    → L3 项目归档 (archive/*.md)
      → L4 全局偏好 (user_profile.md)
      → L5 知识库 (knowledge/*.md)
```

设计思路：层层筛选，越往上越精华。不是什么都记，而是有提炼的过程。

#### 六级闸门系统

为了解决"触发控制"和"质量保证"的问题，设计了六级闸门：

| 闸门 | 解决的问题 |
|---|---|
| G1 Trigger | 什么时候加载 Skill，避免误触发 |
| G2 Intent | 真的要做还是随口提 |
| G3 Quality | 这件事值不值得做（防止生成空洞内容） |
| G4 Process | 按多完整的流程走（繁简控制） |
| G5 Write | 能不能写入文件（写入保守度） |
| G6 Safety | 破坏性操作保护（安全底线） |

每道闸门有 strict/medium/loose 三档，还有快速预设。

#### 三级灵活度原则

为了解决"Skill 规则和 AI 原生推理打架"的问题：

- 🔴 刚性规则（Must）— 安全底线，绝对不能碰
- 🟡 推荐流程（Should）— 建议遵循，但有更好的做法可以偏离
- 🟢 可选建议（May）— 仅供参考，自由发挥

核心思想：**Skill 是默认剧本，不是铁律**。AI 可以灵活调整，但安全底线不能碰。

### 功能清单

**核心功能（5 个）**：
1. 项目归档 — 生成结构化归档文档，提炼经验
2. 知识库检索 — 跨项目搜索相关经验
3. 记忆整理 — 去重、合并、分类优化
4. 偏好复盘 — 从历史中提炼稳定偏好
5. 状态概览 — 统计仪表盘

**辅助功能（3 个）**：
1. 帮助信息 — 使用说明和命令速查
2. 健康检查 — 记忆系统完整性检测
3. 配置管理 — 对话中调闸门配置

### 技术选型

| 决策 | 方案 | 原因 |
|---|---|---|
| 实现形式 | TRAE 自定义 Skill（纯 Markdown） | 利用 TRAE 现有能力，零额外依赖 |
| 存储格式 | 纯 Markdown | 人类可读、易编辑、Git 友好 |
| 配置方式 | 独立配置文件（memory-config.md） | 配置驱动，用户不用改核心逻辑 |
| Skill 类型 | 全局 Skill | 记忆管理是跨项目的能力 |
| 知识库分类 | 4 大类（技术栈/踩坑/最佳实践/模式） | 平衡粒度，不粗也不细 |

### 踩坑记录

#### 1. Git 全局配置权限问题

**问题**：在 TRAE 沙箱中执行 `git config --global` 报错 `Permission denied`，因为沙箱不让写用户目录的 `.gitconfig` 文件。

**解决方案**：让用户手动在终端执行一次配置命令。

**经验**：TRAE 的命令执行是在沙箱里的，涉及用户全局配置的操作可能受限。

#### 2. GitHub MCP 权限不足

**问题**：`create_repository` 接口返回 403，提示 "Resource not accessible by integration"。

**解决方案**：改用浏览器手动创建仓库，然后用 `push_files` 接口推送代码（这个接口有权限）。

**经验**：GitHub 插件的权限范围有限，不是所有操作都能做。推送文件是 OK 的，但创建仓库不行。

#### 3. PowerShell 路径问题

**问题**：每次 `RunCommand` 后工作目录会重置，不是持久的。

**解决方案**：用 `cwd` 参数指定每次命令的工作目录，而不是依赖 `cd`。

**经验**：TRAE 的命令执行是无状态的，每次调用都是独立的。

### 遗留问题 / 待办

以下功能目前只有框架，没有细化实现：

- [ ] **知识库检索算法** — 目前只有"多维度匹配"的描述，具体怎么匹配、怎么排序还没细化
- [ ] **记忆整理算法** — 重复检测、矛盾检测的具体方法没定
- [ ] **偏好复盘算法** — 模式识别的具体标准和置信度计算还很粗略
- [ ] **可视化** — 记忆仪表盘、归档报告美化、内联卡片都还没做
- [ ] **Git 集成** — 归档时自动读 Git log 和 diff，目前还没实现
- [ ] **备份机制** — `.backup/` 目录的自动创建和清理逻辑还没实现
- [ ] **增量复盘** — 只分析上次复盘后的新内容，不用全量扫

### 后续方向

1. **先做可视化** — 记忆概览的 HTML 仪表盘，体验提升最明显
2. **细化归档功能** — Git 集成、Spec 文档联动，提升归档质量
3. **细化检索** — 标签+关键词混合检索，先把基础的做好
4. **实测迭代** — 在真实项目中多测几次，根据反馈调整闸门阈值和流程
